# culture-today

영화·책·전시·공연·음악을 다루는 문화 매체 **오늘의 문화**의 퍼블리싱 프로젝트입니다.

## 프로젝트 구조

```text
src/
├── content/articles/  # 기사별 Markdown 파일
├── data/              # 사이트·카테고리·메뉴 설정
├── templates/
│   ├── pc/            # PC 레이아웃·메인·목록·상세
│   ├── mobile/        # 모바일 레이아웃·메인·목록·상세
│   └── partials/      # PC·모바일 헤더, 공유 푸터·기사 카드
└── assets/
    ├── styles/        # 스타일
    ├── scripts/       # 브라우저 JavaScript
    └── images/        # 이미지
scripts/               # Node.js 빌드·샘플 기사 생성 코드
docs/                  # 구현 결정·QA 기록
dist/                  # 빌드 결과 (Git 제외)
```

기사와 설정을 LiquidJS에 전달해 정적 HTML을 생성하는 방식으로 진행합니다.
메인 주요 기사는 `src/data/home.json`의 `featuredArticles`에 기사 `slug`를 표시할 순서대로 지정합니다.
메인 주요 기사 슬라이드는 이 설정의 순서대로 표시합니다.
PC와 모바일 모두 이미지 위에 제목과 요약을 겹치는 배너로 표시합니다. PC 콘텐츠의 최대 폭은 1000px입니다.
4초 자동 전환과 이전·다음 버튼, 기사 선택 점을 순수 JavaScript로 구현합니다. 직접 전환하면 4초를 다시 계산합니다.
마우스를 올려도 계속 전환합니다. 기사 링크에 포커스하거나 다른 브라우저 탭으로 이동하면 잠시 멈추고, 돌아오면 4초 뒤부터 재개합니다.
동작 줄이기 설정에서는 자동 전환을 멈추고 버튼으로 기사를 선택할 수 있습니다. JavaScript가 없으면 주요 기사 전체를 표시합니다.
추천 기사는 같은 파일의 `recommendedArticles`에 카테고리별 기사 slug 4개를 노출 순서대로 지정합니다.
Liquid로 각 카테고리의 기사 목록을 생성하고, 순수 JavaScript로 선택한 탭의 목록을 표시합니다.
PC는 4열, 모바일은 세로로 배치합니다. 방향키·Home·End로 탭을 선택하고 Tab으로 기사 링크에 이동합니다.
JavaScript가 없으면 카테고리 이름과 모든 추천 기사 목록을 표시합니다.
최신 기사 영역은 발행일 내림차순으로 정렬된 기사 중 10개를 Liquid로 출력합니다.
카테고리·제목 링크와 요약·작성자·발행일을 표시하며, 이미지가 없는 기사는 텍스트만 표시합니다.
카테고리별 15개씩, 총 75개의 창작 샘플 기사를 Markdown 파일로 관리합니다.
실제 작품·행사의 소식이나 취재 기사가 아니며 각 본문에 시연용 콘텐츠임을 표시했습니다.
발행일은 샘플 정렬용 데이터입니다. 전체 기사 75개에 AI로 생성한 WebP 이미지를 연결했습니다.
카테고리별 범용 이미지 3장씩 총 15장을 같은 카테고리 안에서 재사용합니다.
이미지 원본은 `docs/image-originals/`에 보관합니다.
화면 스타일은 흐름 확인용이며 최종 매체 디자인은 아직 구현하지 않았습니다.

헤더·푸터에는 흰색·먹색·짙은 초록색을 적용했습니다.
PC 헤더는 다섯 카테고리를 바로 표시하고, 모바일 헤더는 메뉴 버튼으로 펼칩니다.
모바일 메뉴는 Enter·Space로 조작하며 Escape로 닫으면 버튼으로 포커스를 돌려줍니다.
JavaScript가 실행되지 않을 때도 카테고리 링크를 표시합니다.
푸터는 두 화면이 같은 템플릿을 공유하며 매체 소개·샘플 콘텐츠 안내·GitHub 링크를 제공합니다.

PC·모바일 HTML을 각각 `dist/pc/`, `dist/mobile/`에 생성합니다.
기사 데이터와 공개 링크 주소는 공유합니다. `vercel.json`의 rewrite 규칙이
요청의 User-Agent에 `Mobile`, `Android`, `iPhone`, `iPad`, `iPod`가 있으면
모바일 HTML, 그 외에는 PC HTML을 같은 URL로 전달하도록 설정되어 있습니다.
화면 너비 변경만으로 화면 종류를 바꾸지 않습니다.
기기 판별은 제한적이며 PC 모드로 요청하는 태블릿은 PC로 분류될 수 있습니다.
Vercel 설정은 작성했지만 이번 변경의 실제 배포 동작은 아직 확인하지 않았습니다.

빈 폴더의 `.gitkeep` 파일은 Git에 폴더 구조를 기록하기 위한 자리 표시자입니다.

## 스타일 기반

순수 CSS를 사용합니다. 페이지에서는 `reset.css` 다음에 `base.css`를 연결합니다.
공통 레이아웃에 두 파일을 연결했습니다.
PC·모바일 레이아웃 모두 동일한 두 CSS 파일을 사용합니다.
base.css에는 폰트 정의·색상 변수·body 기본값만 둡니다.
영역과 페이지의 스타일은 해당 Liquid의 `<style>`에 두고, 영역 클래스로 CSS 적용 범위를 나눕니다.
PC·모바일 헤더는 각각의 템플릿에서 스타일을 출력합니다. 공통 영역은 `device`를 전달해 해당 기기의 스타일만 출력합니다.
목록·상세 페이지는 아직 흐름 확인용 디자인입니다.

기본 글꼴은 Pretendard Variable v1.3.9입니다. 공식 폰트를
`src/assets/fonts/pretendard/`에 저장해 사용하며 SIL Open Font License 1.1을 함께 보관합니다.
`font-display: swap`으로 다운로드 중에는 시스템 글꼴을 표시합니다.
전체 글꼴 파일로 시작하며, 페이지 구성 후 용량과 로딩을 확인해 서브셋 적용 여부를 검토합니다.

출처: https://github.com/orioncactus/pretendard/tree/v1.3.9

## 실행

메인 `/` → 영화 목록 `/category/movie/` → 상세 `/articles/test-film/` 순서로
이동할 수 있습니다. 나머지 카테고리는 같은 목록 템플릿으로 빈 목록을 표시합니다.

`src/content/articles/test-film.md`의 기본 정보는 `@11ty/gray-matter`로 읽고,
본문은 `markdown-it`으로 HTML로 변환합니다. 두 도구 모두 빌드에서만 실행합니다.
본문의 직접 작성한 HTML은 해석하지 않습니다.
필수 항목·카테고리·발행일·slug 형식과 중복·이미지 항목 오류는 빌드를 중단합니다.
이미지 항목을 생략하면 템플릿에 전달할 때 `null`로 정리합니다.

Node.js v20.14.0과 npm 10.7.0에서 확인했습니다.

```sh
npm ci
npm run dev
```

`http://localhost:3000`에서 확인합니다. `src` 파일을 추가·수정·삭제하면
다시 빌드하고 브라우저를 새로고침합니다. 빌드 코드 변경 시 개발 서버를 재시작합니다.
템플릿 변수·필터 오류는 터미널에 표시하며, 수정 후 저장하면 다시 빌드합니다.
로컬에서도 Vercel 설정의 같은 User-Agent 패턴으로 화면을 선택합니다.
개발자 도구에서 모바일 기기 에뮬레이션으로 User-Agent를 바꾼 뒤 새로고침하면
모바일 HTML을 확인할 수 있습니다. 너비만 바꾸는 것으로는 전환되지 않습니다.
`vercel.json`의 판별 패턴을 수정하면 개발 서버를 재시작합니다.

## Vercel 배포

프레임워크 자동 감지를 끄고 `npm run build` 결과인 `dist`를 배포하도록 설정했습니다.
메인·목록·상세 URL에만 기기별 rewrite를 적용하며 정적 자산은 공통 경로를 사용합니다.
응답에 `Vary: User-Agent`를 설정했습니다. 배포 후 PC·모바일 요청을 번갈아 보내
올바른 HTML이 전달되는지, 캐시된 응답과 직접 URL 접속도 함께 확인해야 합니다.

```sh
npm run build
```

빌드할 때 `dist`를 비우고 HTML과 정적 자산을 생성합니다.
LiquidJS는 Node.js에서만 실행하고, Vite는 개발 미리보기·파일 감지·새로고침에만 사용합니다.
운영 빌드는 기존 LiquidJS 스크립트가 담당합니다. 배포 파일에는 Vite 개발 클라이언트가 포함되지 않습니다.

BrowserSync의 간접 의존성에서 보고된 보안 이슈 때문에 미리보기 도구를 Vite로 교체했습니다.
교체 후 npm audit 결과는 0건입니다. 이 결과는 운영 사이트 전체의 취약성 검증을 의미하지 않습니다.
